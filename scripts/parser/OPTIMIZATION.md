# 🚀 Оптимизация парсера: Параллельная обработка

**Дата:** 10 декабря 2025
**Версия:** 2.0 (TaskGroup + Semaphore)

## Проблема
Парсинг статей выполнялся последовательно - каждая следующая статья ждала завершения предыдущей.
**Время на 8 статей:** ~23 секунды (~3 сек/статья)

## Решение v2.0
Внедрена **параллельная обработка** через `asyncio.TaskGroup()` + `asyncio.Semaphore()`.

**Upgrade с v1.0:** Изначально использовали `asyncio.gather()`, но перешли на TaskGroup для лучшей обработки ошибок и Semaphore для точного контроля параллелизма.

### Ключевые изменения

1. **`asyncio.Semaphore(batch_size)`** - точный контроль количества параллельных запросов
2. **`asyncio.TaskGroup()`** - структурированное управление задачами + автоотмена при ошибках
3. **`fetch_article_with_semaphore()`** - функция с семафором для ограничения конкуренции
4. **`except* ExceptionGroup`** - graceful обработка групповых ошибок
5. **Параметр `--batch-size`** - управление семафором (по умолчанию 5)

## Технические детали

### Реализация

```python
# Разбивка на батчи
for batch_start in range(0, len(articles), batch_size):
    batch = articles[batch_start:batch_start + batch_size]

    # Создаём задачи
    tasks = [fetch_article_batch(...) for article in batch]

    # Выполняем параллельно
    results = await asyncio.gather(*tasks, return_exceptions=True)
```

### Преимущества `asyncio.gather()`
1. ✅ Простая реализация
2. ✅ Автоматическая обработка исключений (`return_exceptions=True`)
3. ✅ Сохранение порядка результатов
4. ✅ Эффективное использование I/O wait time

### Альтернативы (рассмотрены, но не реализованы)
- `asyncio.TaskGroup` (Python 3.11+) - более новое API, но функционально аналогично
- `asyncio.as_completed()` - сложнее в реализации для checkpoint'ов
- Thread pool - не подходит для async/await

## Безопасность

✅ **Checkpoint'ы сохраняются после каждого батча**
✅ **Обработка ошибок не блокирует другие задачи**
✅ **Можно продолжить с любого места через `--start-from`**

## Лимиты

**Не рекомендуется:**
- `batch_size > 10` - может вызвать rate limiting на сервере
- `batch_size = 1` - теряется весь смысл оптимизации

**Оптимально:**
- `batch_size = 3-7` для стабильной работы
- `batch_size = 5` для баланса скорости и надёжности
